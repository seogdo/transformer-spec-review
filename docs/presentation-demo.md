# 변압기 수주 기술사양 검토 AI 발표와 시연

수주 확정 후 기술 인계회의 전에 고객 요구와 승인 변경이 내부 인계표에 반영됐는지 확인하는 로컬 웹 프로토타입입니다. 발표에서는 **변경 미반영 발견 → 양쪽 원문 확인 → 담당자 판단**의 흐름을 보여줍니다.

## 3분 발표 대본

### 문제와 사용 시점

안녕하세요. 변압기 수주 기술사양 검토 AI를 소개하겠습니다.

수주가 확정된 이후에도 고객 사양서와 변경 합의서, 내부 인계표를 함께 확인해야 합니다. 변경된 요구사항이 인계표에 반영되지 않으면 이후 업무에서 혼선이 생길 수 있습니다. 이 프로젝트는 기술 인계회의 전에 문서 간 차이를 찾고, 담당자가 원문을 확인하도록 돕는 것을 목표로 했습니다.

### 처리 방식

입력은 고객 사양서, 기술 변경 합의서, 내부 수주 인계표의 PDF 3종입니다. 먼저 고객사 표기가 같은 등록 후보인지 확인합니다. 이후 로컬 AI가 사양 항목의 근거를 검색하고 값과 출처를 제안합니다.

AI가 제안한 내용을 그대로 판정에 사용하지는 않습니다. 코드가 원문 근거를 대조하고, 담당자가 적용할 승인 변경을 확인한 다음 10개 기술사양을 비교합니다. 근거가 부족하거나 값이 모호한 항목은 확인 필요로 남깁니다.

### 대표 사례 시연

지금 보여드리는 것은 직접 구성한 가상 문서입니다. 변경 합의서에는 팬 전원이 440 V로 바뀌었지만, 내부 인계표에는 380 V가 남아 있습니다.

검토 결과에서 팬 전원 항목을 선택하면 요구값과 인계값, 문서명과 페이지, 양쪽 원문을 함께 볼 수 있습니다. 단순히 불일치라고 알려주는 데서 끝나는 것이 아니라 담당자가 어떤 내용을 확인해야 하는지 연결했습니다.

### 검증과 한계

V01 가상 문서의 실제 로컬 AI 시험에서 21개 추출값이 원문 대조를 통과했고, 10개 기술 항목은 9개 일치와 1개 불일치로 표시됐습니다. 자동 검사 349개와 화면 모의 검사 44개도 통과했습니다. 이 수치는 개발 사례의 동작 확인이며 실제 회사 문서 정확도를 의미하지는 않습니다.

AI 연결 실패 시에는 값을 임의로 만들지 않고 보류합니다. 응답 오류 후 다시 요청하더라도 같은 작업을 확인하도록 보완했습니다.

현재는 지정된 메타데이터가 있는 가상 텍스트 PDF를 지원합니다. 스캔 문서나 도면은 지원하지 않으며, 설계 적합성이나 제품 안전을 승인하지 않습니다. 최종 판단은 담당자가 수행합니다. 감사합니다.

## 화면 진행 순서

아래 시간은 발표 배분안이며 처리시간 보장이 아닙니다. 추출 대기 중에 처리 구조를 설명하면 화면이 멈춘 것처럼 보이는 시간을 줄일 수 있습니다.

| 구간 | 화면 조작 | 설명할 내용 |
| --- | --- | --- |
| 0:00–0:20 | 첫 화면을 보여줍니다. | 수주 확정 후 기술 인계 전의 문서 정합성 확인입니다. |
| 0:20–0:40 | **V01 · 텍스트 문서**를 누르고 고객사 카드 3개를 봅니다. | PDF 3종을 읽고 같은 고객사 후보인지 먼저 확인합니다. |
| 0:40–1:35 | **AI로 근거 찾고 항목 추출**을 한 번 누릅니다. | 로컬 AI 검색·추출, 코드의 원문 대조, 담당자 확인의 역할을 설명합니다. |
| 1:35–2:20 | 추출 완료 후 적용할 승인 변경을 확인하고 기준 확인란을 체크합니다. **10개 항목 검토하기**를 누른 뒤 **확인 필요 항목** 필터와 팬 전원 행을 선택합니다. | 440 V와 380 V의 차이 및 양쪽 근거를 보여줍니다. |
| 2:20–2:40 | 담당자가 원문을 확인한 뒤 결과 저장 영역을 보여줍니다. | JSON 기록 저장은 설계 승인·제작 지시가 아닙니다. |
| 2:40–3:00 | 결과 화면을 유지합니다. | 실제 시험 결과와 지원 범위, 보류 원칙을 정리합니다. |

실시간 결과가 다르면 실제 표시를 그대로 설명합니다. 9일치·1불일치를 만들기 위해 파일이나 결과를 수정하지 않습니다. **AI 구조 확인 요청**은 이미 계산된 결과의 구조를 점검하는 별도 선택 기능이므로 주 시연에서는 생략합니다.

## 발표 전 준비

- 앱은 README의 실행 방법으로 켜고 `http://127.0.0.1:8765`에서 서버 연결 상태를 확인합니다.
- Ollama와 이미 설치된 `qwen3.5:2b`를 준비합니다. 기본 연결 주소는 `http://127.0.0.1:11434`입니다. 발표 전에 V01을 한 번 실행해 해당 환경의 연결과 시간을 확인합니다.
- 회사 문서 대신 저장소에 포함된 가상 PDF를 사용합니다. 고객사 이름은 비교 기능을 위한 후보이며 실제 거래 관계를 뜻하지 않습니다.
- 저장된 검토 결과와 [기존 시험 화면](../output/live-browser-v01-result.png)을 대체 자료로 준비합니다. 과거 화면은 실시간 실행이라고 소개하지 않습니다.
- JSON 다운로드는 사람이 결과와 원문을 확인한 뒤 진행합니다. PDF 뷰어의 다운로드 버튼은 완료 검증이 남아 있으므로 필수 시연에 넣지 않습니다.

## 연결이 느리거나 실패할 때

추출 접수 응답이 불명확하면 **같은 추출 요청 다시 확인**을 사용합니다. 계속 버튼을 반복해서 누르거나 새 예시를 연속 생성하지 않습니다.

AI 연결이 실패하면 확인 필요 결과와 안내를 그대로 보여주고, “실패한 값을 만들어내지 않고 검토를 보류합니다”라고 설명합니다. 시간이 부족하면 준비한 저장 결과로 전환해 “이 화면은 사전 실제 실행 결과입니다”라고 구분합니다.

AI 없이 비교 기능만 보여줘야 한다면 **예시 01 · 변경 검토**를 선택할 수 있습니다. 이 경로는 정형 PDF를 코드로 읽으므로 AI 추출 시연이라고 소개하지 않습니다.

## 질의응답 핵심

**일반 규칙 비교와 AI의 차이**

AI는 지원하는 텍스트 문서에서 검색 계획을 만들고 근거에 연결된 값을 제안합니다. 비교·단위 정규화·변경 적용은 코드로 처리해 역할을 분리했습니다.

**승인된 문서는 어떻게 확인하는지**

현재 승인 정보는 가상 문서의 입력 메타데이터입니다. 담당자가 적용 관계를 확인하지만 전자서명, 승인 권한, 문서 진위를 인증하지는 않습니다.

**검색은 어떤 방식인지**

키워드와 지정 별칭을 사용하는 제한된 근거 검색입니다. 임베딩 기반 벡터 검색이나 MCP를 구현했다고 설명하지 않습니다.

**현업 적용에 더 필요한 내용**

실제 문서 형식과 접근 권한, 승인 이력 연결, 독립 평가 자료, 운영 보안 검토가 필요합니다. 현재 가상 문서 시험 결과를 현업 정확도로 환산하지 않습니다.

## 최종 보고서 구성

보고서나 슬라이드는 문제와 사용 시점, 입력 문서와 범위, AI와 코드의 역할, 대표 불일치 화면, 검증 결과, 한계와 후속 작업 순서로 구성합니다. 테스트 개수와 모델 정확도를 구분하고 시간 절감률처럼 측정하지 않은 결과는 넣지 않습니다.
