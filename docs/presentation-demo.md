# 변압기 수주 기술사양 검토 AI 5분 발표와 시연

**G077 문성도 / 과제 2**입니다. 수주 확정 후 기술 인계회의 전에 고객 요구와 승인 변경이 내부 인계표에 반영됐는지 확인하는 로컬 웹 프로토타입입니다.

최신 공지에 맞춰 **앞 2분은 주제·주요 task·결과, 뒤 3분은 직접 작성한 코드**를 설명합니다. 발표자료는 **본 발표 9장과 부록 9장, 총 18장**입니다. 앞 2분에는 1~4장, 뒤 3분에는 5~9장을 사용합니다. 저장된 실제 실행 캡처를 주 자료로 사용하고 실시간 AI 추출은 선택 시연으로 분리합니다. 아래 장 번호와 페이지명을 함께 확인합니다. 추가 코드 질의응답은 부록이며, 핵심 코드 설명 자체는 5분 본 발표에 포함됩니다.

## 5분 발표 대본

### 0:00–0:25 · 주제와 사용 시점

화면: **1장 변압기 수주 기술사양 검토 AI**, **2장 문제와 사용 시점**

안녕하세요. G077 문성도입니다. 과제 2로 변압기 수주 기술사양 검토 AI를 만들었습니다. 수주가 확정된 뒤 기술 인계회의 전에 고객 요구와 변경 합의가 내부 인계표에 반영됐는지 확인하는 서비스입니다. 문서 간 차이를 찾고 담당자가 원문을 확인하도록 돕는 것이 목적입니다.

### 0:25–0:50 · 주요 task

화면: **3장 입력 문서와 주요 task**. 역할 구분과 회의용 보고서는 말로만 소개하고 부록으로 이동하지 않습니다.

입력은 고객 사양서, 변경 합의서, 내부 인계표의 PDF 세 종류입니다. 고객사를 확인하고 근거를 검색해 값을 추출한 다음, 담당자가 적용할 변경을 확인하면 열 개 사양을 비교합니다. 양쪽 원문을 연결하고 결과 저장과 회의용 보고서까지 제공합니다.

### 0:50–1:25 · 실제 실행 결과

화면: **4장 최종 실행 결과: 440 V와 380 V**. 회의용 보고서 기능은 언급만 합니다.

이 화면은 직접 만든 가상 문서로 사전에 실제 실행한 결과입니다. 변경 합의서의 팬 전원 요구는 440 V인데 내부 인계표에는 380 V가 남아 있습니다. 결과는 아홉 항목 일치와 한 항목 불일치였습니다. 담당자는 값뿐 아니라 문서명, 페이지, 양쪽 원문을 함께 확인할 수 있습니다. 검토 기록은 저장하고 회의용 보고서로 열 수 있습니다.

### 1:25–2:00 · 검증, 느낀 점과 개선 방향

화면: **4장 최종 실행 결과: 440 V와 380 V**를 그대로 유지합니다. 화면의 385개·65개 검사 요약과 가상 문서 한계를 짚고, 느낀 점·향후 개선은 말로 설명합니다. 별도 검증표·한계 부록으로 이동하지 않습니다.

Python 자동 검사 385개와 화면 모의 검사 65개를 통과했습니다. 다만 이 개수는 실제 회사 문서의 AI 정확도가 아닙니다. 구현하면서 답을 만드는 것만큼 근거를 연결하고 애매한 값을 보류하는 과정이 중요하다는 점을 확인했습니다. 현재는 지정 형식의 가상 텍스트 PDF를 지원하며, 다음에는 별도의 문서 평가와 검색 방식·처리 지연 비교가 필요합니다. 설계 승인과 안전 판단은 수행하지 않습니다.

### 2:00–2:45 · Agent 실행 구조와 미사용 기술

화면: **5장 Agent 실행 흐름과 호출 제어**. Python 실행 순서와 호출 예산의 실제 코드를 보여줍니다.

코드는 `extract_upload`에서 시작합니다. 첫 모델 호출로 검색 계획을 받고, Python이 검색 함수를 실행합니다. 근거가 있으면 두 번째 모델 호출로 값을 제안받고 검증합니다. 검색 결과가 없으면 두 번째 호출을 생략합니다. 호출은 최대 두 번이며 전체 제한시간을 확인합니다. 이 실행 순서는 Python 제어 흐름이고 LangGraph의 실행 그래프는 아닙니다. Multi-Agent, MCP, LangGraph, LangSmith는 사용하지 않았습니다. MCP 서버 연결 대신 프로젝트 내부 검색 함수를 직접 호출했습니다.

코드 위치: [extract_upload 시작](../src/handoff_review/extraction_agent.py#L573), [호출 횟수·제한시간 검사](../src/handoff_review/extraction_agent.py#L599), [검색 계획·검색 실행·근거 없음 분기](../src/handoff_review/extraction_agent.py#L613), [두 번째 추출 요청](../src/handoff_review/extraction_agent.py#L632).

### 2:45–3:30 · 키워드 기반 RAG

화면: **6장 코드 설명 1 근거 검색**

`_search_documents`의 입력은 문서 ID, 검토 항목과 검색어입니다. 지정 별칭으로 찾은 원문에 검색어 포함 점수를 매기고 페이지와 위치 순으로 정렬합니다. 검색 요청별 상위 두 개를 문자 예산 안에서 반환하며 문서 ID, 페이지, 인용문을 함께 보존합니다. 반환한 근거는 다음 AI 추출 요청에 전달합니다. 이 부분이 검색 기반 생성 경로이며, 임베딩 벡터 검색은 사용하지 않았습니다. 검색에서 놓친 정보까지 알아낸다고 보장하지 않습니다.

코드 위치: [_search_documents](../src/handoff_review/extraction_agent.py#L300), [핵심 검색 발췌 314–325행](../src/handoff_review/extraction_agent.py#L314), [검색 결과를 추출 요청에 전달](../src/handoff_review/extraction_agent.py#L654).

### 3:30–4:15 · 원문과 제안값 검증

화면: **7장 코드 설명 2 원문과 제안값 검증**

`_validate_proposal`은 AI 인용이 실제 페이지와 검색 결과에 있는지 확인합니다. 화면의 수치 분기에서는 원문과 인용에 같은 값과 단위가 있는지, 해당 항목명에 직접 연결되는지를 검사합니다. 숫자가 문서 어딘가에 있다는 이유만으로 채택하지 않습니다. 미확정이나 부정 문맥, 여러 값과 조건이 있으면 거절 이유를 남기고 보류합니다. 확인되지 않은 값을 코드가 대신 만들어 넣지는 않습니다.

코드 위치: [_validate_proposal](../src/handoff_review/extraction_agent.py#L497), [수치 검증 발췌 544–551행](../src/handoff_review/extraction_agent.py#L544), [거절된 제안의 보류 처리](../src/handoff_review/extraction_agent.py#L672).

### 4:15–4:40 · 사양 비교

화면: **8장 코드 설명 3 사양 비교와 보류**

최종 비교는 `review_case`가 수행합니다. 먼저 명시된 변경 적용 관계를 확인하고 단위와 조건을 맞춥니다. 같은 값은 일치, 다르면 불일치이고 출처나 조건이 불확실하면 확인 필요입니다. 승인 표시는 데모 메타데이터이며 실제 결재 권한을 인증하지는 않습니다.

코드 위치: [review_case](../src/handoff_review/review.py#L40), [변경 관계 확인](../src/handoff_review/review.py#L122), [비교·보류 발췌 189–200행](../src/handoff_review/review.py#L189).

### 4:40–5:00 · 의존성 주입과 마무리

화면: **9장 코드 설명 4 의존성 주입과 테스트**

`request_fn`에 고정 응답 함수를 넣으면 실제 AI 없이 같은 조건을 반복 검사할 수 있습니다. 예시 검사는 두 번의 요청과 입력 보존을 확인합니다. PDF 처리, 추출, 비교와 API를 모듈로 나누고, 불확실한 값은 담당자에게 남기도록 구현했습니다. 감사합니다.

코드 위치: [request_fn 선택](../src/handoff_review/extraction_agent.py#L593), [고정 응답 시험 86–94행](../tests/test_extraction_agent.py#L86).

## 선택 실시간 시연

교수자가 추가 시연을 요청하거나 별도 시간이 있을 때만 진행합니다. 발표 전 해당 환경에서 연결·소요시간을 확인하며 처리시간을 보장하지 않습니다.

1. **V01 · 텍스트 문서**를 선택하고 고객사 카드 3개를 확인합니다.
2. **AI로 근거 찾고 항목 추출**을 한 번 누릅니다. 대기 중에는 AI의 계획·값 제안과 코드의 검색·검증을 구분해서 설명합니다.
3. 추출이 끝나면 적용할 승인 변경을 확인하고 기준 확인란을 체크합니다. **10개 항목 검토하기**를 누릅니다.
4. **확인 필요 항목** 필터와 팬 전원 행을 선택해 실제 결과와 양쪽 원문을 확인합니다.
5. 담당자가 원문을 확인한 뒤 **회의용 보고서 열기**를 보여줍니다. JSON·PDF 저장은 설계 승인·제작 지시가 아닙니다.

실시간 결과가 다르면 실제 표시를 그대로 설명합니다. 9일치·1불일치를 만들기 위해 파일이나 결과를 수정하지 않습니다. **AI 구조 확인 요청**은 이미 계산된 결과의 구조를 점검하는 별도 선택 기능이므로 본 발표에서는 생략합니다.

## 코드 설명 준비

[핵심 코드 설명](code-walkthrough.md)의 실행 근거를 뒤 3분 본 발표에 사용합니다. 검색, 값·인용 검증, 사양 비교, 의존성 주입의 핵심 코드 페이지를 미리 열고, 발표 후 추가 질문은 부록과 전체 함수로 답합니다.

- 검색은 지정 별칭으로 찾은 구간을 검색어 점수로 정렬합니다. 상위 근거를 다음 AI 요청에 전달합니다.
- 검증은 숫자가 문서에 있다는 사실뿐 아니라 해당 항목에 값·단위가 직접 연결됐는지 확인합니다.
- 비교는 명시된 변경 관계로 기준을 구성하고 단위와 운전조건을 맞춰 수행합니다. 불확실하면 보류합니다.
- 모델 요청 함수는 시험에서 고정 응답 함수로 교체합니다. 이 검사와 실제 AI 정확도는 구분합니다.

## 연결이 느리거나 실패할 때

추출 접수 응답이 불명확하면 **같은 추출 요청 다시 확인**을 사용합니다. 계속 버튼을 반복해서 누르거나 새 예시를 연속 생성하지 않습니다.

AI 연결이 실패하면 확인 필요 결과와 안내를 그대로 보여주고, “실패한 값을 만들어내지 않고 검토를 보류합니다”라고 설명합니다. 시간이 부족하면 준비한 저장 결과로 전환해 “이 화면은 사전 실제 실행 결과입니다”라고 구분합니다.

AI 없이 비교 기능만 보여줘야 한다면 **예시 01 · 변경 검토**를 선택할 수 있습니다. 이 경로는 정형 PDF를 코드로 읽으므로 AI 추출 시연이라고 소개하지 않습니다.

## 부록: 질의응답 핵심

**일반 규칙 비교와 AI의 차이**

AI는 지원하는 텍스트 문서에서 검색 계획을 만들고 근거에 연결된 값을 제안합니다. 비교·단위 정규화·변경 적용은 코드로 처리해 역할을 분리했습니다.

**승인된 문서는 어떻게 확인하는지**

현재 승인 정보는 가상 문서의 입력 메타데이터입니다. 담당자가 적용 관계를 확인하지만 전자서명, 승인 권한, 문서 진위를 인증하지는 않습니다.

**검색은 어떤 방식인지**

키워드와 지정 별칭을 사용하는 제한된 근거 검색입니다. 임베딩 기반 벡터 검색이나 MCP를 구현했다고 설명하지 않습니다.

**Agent Graph와 MCP는 어디에 사용했는지**

실행 순서는 Python의 `extract_upload` 안에서 제어합니다. 검색 계획, 내부 검색 함수, 값 제안, 검증·보류 분기를 실제 코드로 설명할 수 있지만 LangGraph `StateGraph`나 Multi-Agent 실행은 아닙니다. MCP 서버·클라이언트와 LangSmith는 연결하지 않았습니다. 공지의 기술명을 모두 사용했다고 맞추는 대신 현재 구현한 RAG·의존성 주입·모듈화·시험의 코드와 미사용 범위를 분명히 설명합니다.

**현업 적용에 더 필요한 내용**

실제 문서 형식과 접근 권한, 승인 이력 연결, 독립 평가 자료, 운영 보안 검토가 필요합니다. 현재 가상 문서 시험 결과를 현업 정확도로 환산하지 않습니다.
