# 변압기 수주 기술사양 검토 AI 5분 발표와 시연

최종 발표의 실행 제공업체는 **OpenAI API**, 사용 모델은 **`gpt-4o-mini`**입니다. 실제 API 실행과 모의 자동검사, 과거 Ollama 기록을 구분합니다. 과거 F01~F06·F04 전후 비교는 OpenAI 결과로 바꾸지 않습니다. [실행 출처와 검증 범위](ai-backends.md)를 함께 확인합니다.

**G077 문성도 / 과제 2**입니다. 수주 확정 후 기술 인계회의 전에 고객 요구와 승인 변경이 내부 인계표에 반영됐는지 확인하는 로컬 웹 프로토타입입니다.

최신 공지에 맞춰 **앞 2분은 주제·주요 task·결과, 뒤 3분은 직접 작성한 코드**를 설명합니다. 발표자료는 **본 발표 9장과 부록 9장, 총 18장**입니다. 앞 2분에는 1~4장, 뒤 3분에는 5~9장을 사용합니다. 저장된 실제 실행 캡처를 주 자료로 사용하고 실시간 AI 추출은 선택 시연으로 분리합니다. 아래 장 번호와 페이지명을 함께 확인합니다. 추가 코드 질의응답은 부록이며, 핵심 코드 설명 자체는 5분 본 발표에 포함됩니다.

## 5분 발표 대본

### 0:00–0:25 · 주제와 사용 시점

화면: **1장 변압기 수주 기술사양 검토 AI**, **2장 문제와 사용 시점**

안녕하세요. G077 문성도입니다. 과제 2로 변압기 수주 기술사양 검토 AI를 만들었습니다. 수주 후 기술 인계회의 전에 고객 요구와 승인 변경이 인계표에 반영됐는지 확인하고, 담당자가 원문을 찾도록 돕는 서비스입니다.

### 0:25–0:50 · 주요 task

화면: **3장 입력 문서와 주요 task**. 역할 구분과 회의용 보고서는 말로만 소개하고 부록으로 이동하지 않습니다.

입력은 고객 사양서, 변경 합의서, 내부 인계표입니다. AI가 근거와 값을 제안하고, 담당자가 적용할 변경을 확인하면 코드가 열 개 사양을 비교합니다. 양쪽 원문을 연결하고 저장한 결과를 회의용 보고서로 엽니다.

### 0:50–1:25 · 실제 실행 결과

화면: **4장 최종 실행 결과: 440 V와 380 V**. 왼쪽은 저장 기록에 근거한 편집 가능한 값·출처 요약, 오른쪽은 저장된 OpenAI V01 보고서의 **팬 전원 양쪽 원문 발췌**입니다. AMD-V01 1쪽의 440 V와 HANDOFF-V01 2쪽의 380 V를 순서대로 가리킵니다. 메인 앱 화면이나 실시간 실행으로 소개하지 않습니다.

결과는 아홉 개 일치와 한 개 불일치입니다. 변경 합의서 1쪽은 팬 전원 440 V를 요구하지만 인계표 2쪽에는 380 V가 남아 있습니다. 오른쪽에서 양쪽 원문을 바로 확인할 수 있습니다. 직접 만든 가상 문서로 OpenAI의 gpt-4o-mini를 사전에 실제 호출한 뒤 저장한 결과입니다.

### 1:25–2:00 · 검증, 느낀 점과 개선 방향

화면: **4장 최종 실행 결과: 440 V와 380 V**를 그대로 유지합니다. 느낀 점·한계·향후 개선을 말로 설명합니다. API 요청·추출값·자동검사 개수는 본 발표에서 나열하지 않고 부록 질문에 답할 때 사용합니다.

구현하면서 답을 만드는 것만큼 근거 연결과 불명확한 값의 보류가 중요하다고 느꼈습니다. 자동검사와 가상 사례의 성공이 현업 AI 정확도를 뜻하지는 않습니다. 현재는 지정 형식의 텍스트 PDF에 한정하며 외부 전송과 과금에 동의한 자료만 사용합니다. 다음에는 독립 문서 평가와 비용·지연 비교가 필요합니다. 설계 승인은 수행하지 않습니다.

### 2:00–2:45 · Agent 실행 구조와 미사용 기술

화면: **5장 Agent 실행 흐름과 호출 제어**. 검색 계획 → 내부 검색 → 값 제안 → 검증 순서를 가리킵니다. 미사용 기술인 Multi-Agent·MCP·LangGraph·LangSmith는 화면과 부록에 명시하며 이름을 하나씩 길게 읽지 않습니다.

`extract_upload`가 순서를 제어합니다. 첫 호출로 검색 계획을 받고 내부 검색 함수를 실행합니다. 근거가 있으면 두 번째 호출로 값을 제안받아 검증하고, 없으면 호출을 생략합니다. 최대 두 번과 전체 90초로 제한하며 다른 제공업체로 자동 전환하지 않습니다. 별도 Graph 프레임워크나 MCP 없이 Python으로 제어합니다.

코드 위치: [extract_upload 시작](../src/handoff_review/extraction_agent.py#L574), [OpenAI·Ollama 요청 선택](../src/handoff_review/extraction_agent.py#L600), [호출 횟수·제한시간 검사](../src/handoff_review/extraction_agent.py#L607), [검색 계획](../src/handoff_review/extraction_agent.py#L624), [검색 실행·근거 없음 분기](../src/handoff_review/extraction_agent.py#L632), [두 번째 추출 요청](../src/handoff_review/extraction_agent.py#L643).

### 2:45–3:30 · 키워드 기반 RAG

화면: **6장 코드 설명 1 근거 검색**. 색으로 강조한 정렬과 `ranked[:2]` 부분을 가리키며 팬 전원 사례를 이어갑니다. 모든 코드를 줄마다 읽지 않습니다.

팬 전원 사례로 보겠습니다. `_search_documents`는 항목 별칭으로 찾은 원문에 검색어 점수를 매깁니다. 강조한 코드가 이를 정렬하고 상위 두 구간을 선택합니다. 문서·페이지·인용문을 보존해 다음 AI 요청에 보내는 키워드 기반 RAG입니다. 벡터 검색은 아니며, 검색에서 놓친 정보를 알아낸다고 보장하지 않습니다.

코드 위치: [_search_documents](../src/handoff_review/extraction_agent.py#L301), [핵심 검색 315–326행](../src/handoff_review/extraction_agent.py#L315), [검색 결과를 추출 요청에 전달](../src/handoff_review/extraction_agent.py#L665). PPT 6장에는 이 중 315–323행을 발췌했습니다.

### 3:30–4:15 · 원문과 제안값 검증

화면: **7장 코드 설명 2 원문과 제안값 검증**. 색으로 강조한 값·단위 대조와 `_direct_binding` 부분을 가리킵니다.

AI가 440 V를 제안해도 바로 채택하지 않습니다. `_validate_proposal`은 인용이 실제 원문과 검색 결과에 있는지 확인합니다. 강조한 부분은 값·단위가 일치하고 팬 전원 항목에 직접 연결됐는지 검사합니다. 숫자가 다른 곳에 있거나 값이 미확정·상충이면 보류합니다. 코드는 확인되지 않은 값을 채워 넣지 않습니다.

코드 위치: [_validate_proposal](../src/handoff_review/extraction_agent.py#L498), [수치 검증 발췌 545–552행](../src/handoff_review/extraction_agent.py#L545), [거절된 제안의 보류 처리](../src/handoff_review/extraction_agent.py#L684).

`review_case`는 승인 변경의 적용 관계와 단위·조건을 확인한 뒤 440 V와 380 V를 비교해 불일치로 표시합니다. 출처나 조건이 불확실하면 보류합니다. 승인 표시는 가상 메타데이터이며 실제 결재 권한 인증은 아닙니다.

코드 위치: [review_case](../src/handoff_review/review.py#L40), [변경 관계 확인](../src/handoff_review/review.py#L122), [비교·보류 189–200행](../src/handoff_review/review.py#L189). PPT 8장에는 이 중 193–200행을 발췌했습니다.

## 선택 실시간 시연

교수자가 추가 시연을 요청하거나 별도 시간이 있을 때만 진행합니다. 발표 전 해당 환경에서 연결·소요시간을 확인하며 처리시간을 보장하지 않습니다.

1. **V01 · 텍스트 문서**를 선택하고 고객사 카드 3개를 확인합니다.
2. 현재 실행 방식 **OpenAI API · gpt-4o-mini**와 전송 범위를 확인합니다. **외부 전송·과금 확인**에 동의한 뒤 **AI로 근거 찾고 항목 추출**을 한 번 누릅니다. 대기 중에는 AI의 계획·값 제안과 코드의 검색·검증을 구분해서 설명합니다.
3. 추출이 끝나면 적용할 승인 변경을 확인하고 기준 확인란을 체크합니다. **10개 항목 검토하기**를 누릅니다.
4. **확인 필요 항목** 필터와 팬 전원 행을 선택해 실제 결과와 양쪽 원문을 확인합니다.
5. 담당자가 원문을 확인한 뒤 **표시된 결과와 원문을 사람이 검토했습니다**를 체크하고, 활성화된 **회의용 보고서 열기**를 보여줍니다. JSON·PDF 저장은 설계 승인·제작 지시가 아닙니다.

실시간 결과가 다르면 실제 표시를 그대로 설명합니다. 9일치·1불일치를 만들기 위해 파일이나 결과를 수정하지 않습니다. **AI 구조 확인 요청**은 이미 계산된 결과의 구조를 점검하는 별도 선택 기능이므로 본 발표에서는 생략합니다.

## 코드 설명 준비

[핵심 코드 설명](code-walkthrough.md)의 실행 근거를 뒤 3분 본 발표에 사용합니다. 검색, 값·인용 검증, 사양 비교, 의존성 주입의 핵심 코드 페이지를 미리 열고, 발표 후 추가 질문은 부록과 전체 함수로 답합니다.

- 검색은 지정 별칭으로 찾은 구간을 검색어 점수로 정렬합니다. 상위 근거를 다음 AI 요청에 전달합니다.
- 검증은 숫자가 문서에 있다는 사실뿐 아니라 해당 항목에 값·단위가 직접 연결됐는지 확인합니다.
- 비교는 명시된 변경 관계로 기준을 구성하고 단위와 운전조건을 맞춰 수행합니다. 불확실하면 보류합니다.
- 모델 요청 함수는 시험에서 고정 응답 함수로 교체합니다. 이 검사와 실제 AI 정확도는 구분합니다.

## 연결이 느리거나 실패할 때

추출 접수 응답이 불명확하면 **같은 추출 요청 다시 확인**을 사용합니다. 계속 버튼을 반복해서 누르거나 새 예시를 연속 생성하지 않습니다.

OpenAI 연결·인증·사용량·응답 오류가 나면 확인 필요 결과와 안내를 그대로 보여주고, “실패한 값을 만들어내지 않고 검토를 보류하며 Ollama로 자동 전환하지 않습니다”라고 설명합니다. 시간이 부족하면 준비한 OpenAI 저장 결과로 전환해 “이 화면은 사전 실제 실행 결과입니다”라고 구분합니다.

AI 없이 비교 기능만 보여줘야 한다면 **예시 01 · 변경 검토**를 선택할 수 있습니다. 이 경로는 정형 PDF를 코드로 읽으므로 AI 추출 시연이라고 소개하지 않습니다.

## 부록: 질의응답 핵심

**일반 규칙 비교와 AI의 차이**

AI는 지원하는 텍스트 문서에서 검색 계획을 만들고 근거에 연결된 값을 제안합니다. 비교·단위 정규화·변경 적용은 코드로 처리해 역할을 분리했습니다.

**본 발표에서 생략한 상세 수치: API 2/2·추출 21/21·자동검사 444/71**

2/2는 V01에서 완료된 구조화 응답을 받은 요청 수입니다. 21/21은 제안된 값 중 원문 검증을 통과한 수이며, 최종 비교는 10개 항목 중 9일치·1불일치입니다. 별도로 Python 자동검사 444개와 DOM 모의검사 71개가 통과했습니다. 자동검사는 실제 API를 호출하지 않습니다. 네 종류의 수치는 서로 다르며 독립적인 AI 정확도나 실제 청구 금액을 뜻하지 않습니다.

**승인된 문서는 어떻게 확인하는지**

현재 승인 정보는 가상 문서의 입력 메타데이터입니다. 담당자가 적용 관계를 확인하지만 전자서명, 승인 권한, 문서 진위를 인증하지는 않습니다.

**검색은 어떤 방식인지**

키워드와 지정 별칭을 사용하는 제한된 근거 검색입니다. 임베딩 기반 벡터 검색이나 MCP를 구현했다고 설명하지 않습니다.

**Agent Graph와 MCP는 어디에 사용했는지**

실행 순서는 Python의 `extract_upload` 안에서 제어합니다. 검색 계획, 내부 검색 함수, 값 제안, 검증·보류 분기를 실제 코드로 설명할 수 있지만 LangGraph `StateGraph`나 Multi-Agent 실행은 아닙니다. MCP 서버·클라이언트와 LangSmith는 연결하지 않았습니다. 공지의 기술명을 모두 사용했다고 맞추는 대신 현재 구현한 RAG·의존성 주입·모듈화·시험의 코드와 미사용 범위를 분명히 설명합니다.

**현업 적용에 더 필요한 내용**

실제 문서 형식과 접근 권한, 승인 이력 연결, 독립 평가 자료, 운영 보안 검토가 필요합니다. 현재 가상 문서 시험 결과를 현업 정확도로 환산하지 않습니다.
