# 오류 안내와 재시도

잘못된 파일은 업로드 단계에서 거부하고, AI가 값을 얻지 못한 항목은 확인 필요로 남깁니다. 추출 성공 응답을 받지 못했을 때는 **같은 추출 요청 다시 확인**으로 기존 작업을 확인합니다. 새로고침만으로 새 AI 작업을 시작하지 않습니다.

## 사용자 처리 방법

| 화면 상황 | 처리 방법 |
| --- | --- |
| PDF 형식 또는 문서 역할 오류 | 해당 파일을 올바른 PDF로 바꾸고 다시 시도합니다. |
| 서버 연결 오류 | 로컬 서버 실행 상태를 확인한 뒤 다시 확인을 누릅니다. |
| 추출 요청 응답을 받지 못함 | 같은 추출 요청 다시 확인을 누릅니다. 새 요청 식별자로 자동 재실행하지 않습니다. |
| AI 연결 불가로 추출값이 없음 | 현재 방식이 Ollama이면 로컬 서버·모델을, OpenAI이면 서버 키·모델 설정과 계정 접근 권한을 확인합니다. 같은 PDF 3종을 다시 읽거나 같은 예시를 선택해 명시적으로 실행하며, 기존 실패 결과는 유지합니다. 다른 제공업체로 자동 전환하지 않습니다. |
| OpenAI 외부 처리 확인이 필요함 | 외부로 보낼 자료와 과금 안내를 읽고 동의한 경우에만 확인란을 체크합니다. 새로고침 후에는 동의를 다시 확인합니다. |
| 저장된 요청과 현재 AI 설정이 다름 | 기존 작업 결과를 조회해 확인합니다. 다른 제공업체·모델로 같은 요청 번호를 재실행하지 않습니다. 새 실행은 새 문서 읽기와 명시적 동의로 시작합니다. |
| 작업 기록을 찾지 못함 | 안내에 따라 명시적으로 재시도합니다. 문서 기록도 없다면 PDF 3종을 다시 읽습니다. |
| 요청 식별자 저장 실패 | AI 추출 요청을 보내지 않습니다. 브라우저 저장 허용 여부와 공간을 확인하고 다시 시도합니다. |
| 작업과 현재 문서가 다름 | 다른 문서의 결과를 적용하지 않습니다. 문서를 확인해 새로 읽습니다. |
| 승인 변경 선택을 바꿈 | 기존 결과가 초기화됩니다. 적용 기준을 다시 확인한 뒤 검토합니다. |
| 저장된 검토 결과를 복원함 | 저장 당시 선택한 변경서만 복원합니다. 아무 변경서도 선택하지 않은 상태도 유지하며, 적용 기준 확인란은 다시 체크해야 합니다. |
| 저장된 적용 기준이 없거나 현재 문서와 맞지 않음 | 변경서 선택을 모두 해제하고 안내합니다. 저장된 결과는 바꾸지 않으며, 원문과 적용 문서를 직접 확인한 뒤 새 검토를 진행합니다. |

## 실제 화면 시험

아래 오류 주입·복구의 실제 AI 결과는 전환 전 **Ollama 시험 기록**입니다. OpenAI 통신을 모의 함수로 대체한 자동검사 및 새 OpenAI 정상 실행과 구분합니다. OpenAI에서 같은 오류 주입·복구 시나리오를 실제 재실행한 기록으로 소개하지 않습니다.

가상 PDF를 사용해 비 PDF·문서 역할 오류, 올바른 파일로 수정 후 재시도, 적용 확인 전 검토 차단, AI 연결 실패와 복구, 승인 선택 수정 시 결과 초기화를 확인했습니다.

AI 연결 실패에서는 값 0개, 기술 항목 10개 모두 확인 필요로 남았습니다. 연결 복구 후 같은 V01을 새로 읽고 추출한 결과는 원문 대조 통과 값 21개, 기술 항목 9개 일치·1개 불일치였습니다.

별도 시험에서는 실제 작업을 접수한 뒤 성공 응답 202를 의도적으로 503으로 바꿨습니다. 실제 네트워크 단절이 아니라 접수 후 응답 오류를 통제한 시험입니다. 새로고침 후 수동 재시도한 두 요청은 같은 식별자를 사용했고, 저장 작업과 파생 문서는 각각 1개, 실제 모델 호출은 2회였습니다. 비교 결과는 9개 일치·1개 불일치로 유지됐습니다.

## 검증 범위

실제 화면 시험과 자동 모의 검사는 구분합니다. 브라우저 저장 실패·두 탭의 기록 혼입·시간 초과 등의 세부 분기는 회귀 검사로 확인하며, 모든 조합을 실제 브라우저에서 재현한 것은 아닙니다.

2026년 10월 21일 복원 회귀검사에서는 빈 변경서 선택·부분 선택·전체 선택의 유지, 적용 기준 누락·손상 시 선택 해제, 미승인 변경서 차단, 수동 선택 후 재검토, 신규 문서 기본값을 확인했습니다. 복원 과정에서 기존 검토 기록을 수정하거나 새 검토를 자동 요청하지 않습니다.

중복 실행 방지는 로컬 단일 서버 프로세스 범위입니다. 여러 서버가 저장소를 공유하는 운영 환경의 보장은 아닙니다. 고객사 검사와 담당자의 적용 기준 확인은 그대로 필요하며, 가상 문서의 성공 결과를 실제 회사 문서 정확도로 해석하지 않습니다.

과거 Ollama V02·V03의 실제 추출·항목 검토를 확인했고, Ollama V03의 회의용 보고서는 Chrome에서 PDF로 저장했습니다. 새 [OpenAI V01~V03 실행](ai-backends.md#확인한-실제-openai-실행)은 `gpt-4o-mini` 요청 총 6회 완료와 사례별 비교 결과를 확인한 별도 기록입니다. V02의 미기재 주파수 보류는 통신 실패가 아니라 값이 확정되지 않은 상태입니다.

현재 Python 444개·DOM 71개 자동검사는 실제 API를 호출하지 않습니다. 원문 PDF 뷰어의 다운로드 완료 여부, OpenAI 실제 오류 주입·복구, 모든 시간 초과·다중 탭 조합의 실제 화면 시험은 별도 확인 대상입니다.
